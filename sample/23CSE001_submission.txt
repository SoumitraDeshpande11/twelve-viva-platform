Project: Library Management System with B-Tree Indexing

Summary:
I built a library catalog backend in Python + SQLite. The core feature is a
B-tree index on the `isbn` column to speed up book lookups. Without an index,
searching 100k books was a full table scan (O(n)); the B-tree gives O(log n)
lookups. I also added a hash index on `member_id` for O(1) equality lookups on
borrow records.

Design decisions:
- B-tree chosen over hash for `isbn` because we need range queries
  (e.g. ISBN prefix search for a publisher) which hashes can't do.
- Normalized schema to 3NF: books, members, loans tables; foreign keys with
  ON DELETE CASCADE on loans.
- Handled write amplification by batching index updates during bulk import.

Trade-offs:
- B-tree adds storage overhead (~15% extra) and slows inserts slightly.
- Considered a covering index but dropped it to save space.

Testing: seeded 100k rows, measured lookup latency before/after indexing
(dropped from ~80ms to ~0.4ms average).
